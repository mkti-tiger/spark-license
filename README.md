# Spark License v1.0

**ブロックチェーン非露出型ライセンス管理 + 秘密鍵埋込パスキー化**

Symbol Mosaic の発行者特権を活用した、ユーザーがブロックチェーンを意識しないライセンス管理アプローチ

---

## 概要

ブロックチェーン技術をライセンス管理に応用する既存研究は多数存在しますが、本提案は **「エンドユーザーがブロックチェーンの存在を意識しない」** ことを設計の中核に据えた実装アプローチです。

ソフトウェア、メディア、データ、AIモデル、ハードウェア起動許可等への適用を想定。

### 中核となる2つの実装要素

1. **Symbol Mosaic の発行者特権を活用したライセンス管理**
   - Symbol ブロックチェーンの Mosaic 機能を使用
   - 発行者が後からトークン所有権を変更可能（Symbol 固有機能）
   - スマートコントラクトを使わない、発行者直接管理型

2. **秘密鍵埋込パスキー化**
   - 暗号化された秘密鍵を製品本体に埋め込み
   - 復号用パスキーをユーザーに配布
   - ユーザーはブロックチェーン・ウォレット・秘密鍵を持たない
   - 製品が内部的にトークン検証を実行

---

## 既存技術との関係

ブロックチェーンを用いたライセンス管理は以下のような先行技術があります:

- NFT ベースのライセンス管理（複数の特許・実装）
- スマートコントラクトを使ったライセンス取り消し
- 取り消し可能な署名（Revocable Signature）研究

本提案は、これらの先行技術と以下の点で異なるアプローチを取ります:

- ユーザーにウォレットを持たせない
- ユーザーがブロックチェーンを認識しない
- スマートコントラクトではなく、Symbol Mosaic の発行者特権を直接利用
- 顧客体験を「通常のパスキー認証式ライセンス」と同等にする

## 設計の本質

### なぜユーザーからブロックチェーンを隠すのか

既存のブロックチェーンベースのライセンス管理では、ユーザーが以下を求められます:

- ウォレットの作成・管理
- 秘密鍵の保管
- ブロックチェーン操作の理解
- 暗号資産関連の税務処理

これらは多くの一般ユーザーにとって心理的・実務的障壁となります。
結果として、ブロックチェーンベースのライセンス管理は技術好きの顧客層に限定されがちです。

### パスキー化による顧客体験の改善

本アプローチでは:

- 秘密鍵を暗号化して製品に埋め込み
- 復号用パスキーをユーザーに配布
- ユーザー視点では「通常のパスキー認証式ライセンス」
- 内部処理として Symbol トークンを検証

これにより、ブロックチェーンの利点（取り消し可能性、永続性）を活かしつつ、一般市場への展開を可能にします。

### 法的整理

- 顧客との契約は通常のソフトウェアライセンス契約
- ユーザーは暗号資産を所有しない
- 暗号資産取引業の規制対象とならない（ユーザー側）
